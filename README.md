# paths2html

<https://github.com/timabell/paths2html>

License: AGPL-3.0

## About

Pipe a list of file paths to this program and it will generate an html file with the folders as clickable lists that will collapse when you click on them.

This makes it easy to take a massive file list and collapse things that you've looked at or that aren't interesting.

## Demo

It will convert this:

```
abc/x-1.txt
abc/x-2.txt
abc/def/ghi/x-2.txt
abc/x-4.txt
hurrah.txt
```

## Installation

### Download binary release from github

1. Grab the [latest release](https://github.com/timabell/paths2html/releases/latest) for Linux, macOS or Windows,
2. unzip it
3. put the binary somewhere in your `PATH`.

### Nix flake

A Nix flake wrapping the prebuilt GitHub release binaries lives on the [`nix` branch](https://github.com/timabell/paths2html/tree/nix) of this repo. It's auto-updated whenever a release is published.

Run without installing:

```sh
find . | nix run github:timabell/paths2html/nix > /tmp/tree.html
```

Install into your profile:

```sh
nix profile install github:timabell/paths2html/nix
```

Reference from a NixOS / home-manager flake:

```nix
inputs.paths2html.url = "github:timabell/paths2html/nix";
# then: paths2html.packages.${pkgs.system}.default
```

Supported systems: `x86_64-linux` (musl-static, runs on NixOS without patching), `x86_64-darwin`, `aarch64-darwin`.

### From source

```sh
cargo install --git https://github.com/timabell/paths2html
```

## Usage

### Pipe results of `find`

```bash
find . -iname '*.pdf' | sort | paths2html > /tmp/tree.html \
   && xdg-open /tmp/tree.html
```

### Looks for AWOL hashes in md5deep output

```bash
grep "Known file not used" ~/Documents/hashdeep-checksums-verification.txt \
  | sed 's/:.*//'| paths2html \
  | tee tmp.html \
  && xdg-open tmp.html
```

## Development

### Releases

Every push to `main` is built and tested on Linux, macOS and Windows. If there are release-worthy commits since the last tag, a [GitHub release](https://github.com/timabell/paths2html/releases) is created with binaries, checksums and release notes generated by [git-cliff](https://git-cliff.org/), and the flake on the `nix` branch is updated.

Commits prefixed `feat:`, `fix:`, `refactor:`, `perf:`, `doc:`, `security:` or `chore:` are release-worthy and appear in the release notes (see [cliff.toml](.github/cliff.toml)). Anything else, e.g. `ci:` or no prefix, doesn't trigger a release.

Each release bumps the patch version. To bump minor or major, or to force a release when nothing is release-worthy, add a footer to a commit message:

```
feat: add new feature

bump: minor
```

`bump: major` and `bump: patch` work the same way.

Preview release notes:

```sh
./release-notes.sh            # latest release
./release-notes.sh --preview  # unreleased changes
```

### Upgrades

Run all upgrades:

```sh
./upgrades.sh
```

Or individually. Each script refuses to run with staged changes and commits its own result:

| Script | What it does | Needs |
|--------|--------------|-------|
| `upgrade-rust.sh` | Moves `mise.toml` to the latest stable Rust, runs tests | [docker](https://www.docker.com/) |
| `upgrade-crates.sh` | Upgrades crates, including incompatible versions, runs tests | [docker](https://www.docker.com/) |
| `upgrade-actions.sh` | Bumps GitHub Actions in `.github/workflows` to the major version of their latest release | [gh](https://cli.github.com/) |

Cargo runs in the official `rust` docker image. The Rust and crate upgrade commits include a `bump: patch` footer so they trigger a release. The actions upgrade only affects CI, so it does not.
